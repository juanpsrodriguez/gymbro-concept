## Checkpoint 11 — mobile menu interaction fixed

In the mobile-compatible test environment `HTMLDialogElement`/`showModal()` is unavailable, matching the failure mode of Safari versions without reliable native dialog support; the exception occurred before `setOpen(true)`, so the menu never opened. `use client`, `onClick`, pointer events and hydration were present and were not the cause.
- Solution: replaced the imperative native `<dialog>` dependency with a state-controlled `<div role="dialog" aria-modal="true">`. The same real two-line `<button>` now toggles open/closed with `aria-expanded`, `aria-controls`, a contextual pt-BR label, `touch-action: manipulation`, 46 × 44 px target and sufficient stacking order. The existing menu links/copy remain unchanged.

The controlled overlay sits below the unchanged sticky header and above page content, avoiding native top-layer/dialog differences across browsers.
